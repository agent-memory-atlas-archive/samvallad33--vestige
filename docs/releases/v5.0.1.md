# Vestige v5.0.1 release procedure

Status: **release candidate**. Run the required local checks against the current
commit and stop on a failure. Push the release branch and open its PR only after
those checks pass. All six target builds and PR checks must pass before merging
and tagging. Publication requires current owner authorization, reviewed package
dry runs, verified source identity, and all six real archives with checksums.

## Earlier preparation evidence (not a substitute for shipping checks)

The comprehensive local audit passed all 16 checks: workspace tests (995
passed, 12 ignored), workspace Clippy with all targets and warnings denied,
store tests (134 passed), store Clippy, formatting, frozen lockfile, dashboard
type checks/tests/build (593 tests), npm platform tests, release fixtures,
package preview, version checks and diff hygiene. Subsequent focused repairs
were verified with all six real MCP Backfill scenarios, a fresh all-target
Clippy pass, and the complete 88-test initializer suite.

The initializer was packed and run through `npm exec --package=<local-tarball>`
in an isolated home and cache, with install scripts and optional downloads
disabled. It configured the built 5.0.1 binary successfully. Its npm publication
dry run passed; no publication occurred. The registry lookup within that dry
run was unavailable in the sandbox, so registry availability is a separate
owner-side check. The full first-run capture, doctor output and hook timings
are in `v5.0.1-first-run.txt`; it labels the local entrypoint accurately.
The captured eight hooks took 90.15–282.20 ms including process startup.
This is measured macOS fixture evidence, not a guarantee under arbitrary load.

Real four-binary archives and matching checksums were built locally for both
Mac targets and both Linux GNU targets. The ARM Mac optimized binary passed
the Maya receipt/recall scenario. The Intel Mac binary starts on the test Mac.
Both Linux binaries passed the glibc 2.35 ceiling check; ARM Linux answered
MCP initialization directly, and x64 Linux answered under explicit QEMU
emulation. The Windows MSVC and Android archives are **not built locally**:
the required Windows SDK/linker and Android NDK are absent. The six-target
artifact workflow is prepared for the reviewed source after an approved push.
Do not stage the complete npm set or call the release ready before every real
archive is available and verified.

Client hook registration and protocol fixtures passed. Actual client trust,
reload and execution in each supported application, native Windows hook runs,
and native Linux hook timing remain separate verification gates. The free
Lite corpus passed 46/46 using a non-scratch isolated home with its simulated
repository fixture. The installed-adapter test proves noninteractive approval
is refused and an explicitly simulated fixture permit authorizes only one

`v5.0.1-files.json` lists source/config/documentation changes and their purpose.
Generated dashboard hashes are reviewed separately. The shipping audit must record its own current commit and results. Preparation
evidence does not establish the state of a later release commit.

## Local verification

Before installing this version on an existing store, create and verify a
complete pre-upgrade Strata backup using the currently installed version's
backup procedure. Keep its matching previous binary. New salience-adjustment
frames are not understood by older binaries. No live-store upgrade is part of
this preparation.

From the repository root:

```bash
python3 -B scripts/verify-v501.py --output dist/v501-shipping-audit
# Equivalent individual checks:
python3 -B scripts/prepare-release.py check-version --version 5.0.1
cargo test --workspace --no-fail-fast
cargo clippy --workspace -- -D warnings
pnpm install --frozen-lockfile
pnpm --filter @vestige/dashboard check
pnpm --filter @vestige/dashboard test
pnpm --filter @vestige/dashboard build
node --test packages/vestige-init/test/*.test.js
node --test packages/vestige-mcp-npm/tests/*.test.js
python3 -B -m unittest discover -s tests -p test_prepare_release.py
git diff --check
```

Record the full commit and checks together. Fixture archives produced by the
Python unit tests contain labeled text and are not release binaries.

## Prepare real binaries without publishing

The artifact-only workflow is `.github/workflows/prepare-release.yml`. It runs
on PRs to main using their exact head SHA, or takes an immutable commit SHA
when dispatched manually. It checks first-party manifest versions, builds the dashboard, and
builds the same six target families as the product release workflow:

| Target | Archive | Binaries |
|---|---|---|
| `aarch64-apple-darwin` | `.tar.gz` | `vestige-mcp`, `vestige`, `vestige-restore`, `vestige-upgrade` |
| `x86_64-apple-darwin` | `.tar.gz` | the same four |
| `x86_64-unknown-linux-gnu` | `.tar.gz` | the same four; glibc 2.35 floor |
| `aarch64-unknown-linux-gnu` | `.tar.gz` | the same four; glibc 2.35 floor |
| `x86_64-pc-windows-msvc` | `.zip` | the same four, with `.exe` |
| `aarch64-linux-android` | `.tar.gz` | `vestige-mcp`, `vestige-upgrade` |

Each archive is named `vestige-mcp-<target>.<extension>` and has a matching
`.sha256` file. Actions artifacts are staging outputs; no release is created,
no tag is moved, and no npm token is used. Cross-target binaries are not
considered built until all six jobs succeed and their outputs are inspected.

The owner can build the native target locally after the feature checks pass:

```bash
cargo build --locked --release -p vestige-mcp -p vestige-upgrade --target aarch64-apple-darwin
python3 -B scripts/prepare-release.py archive --target aarch64-apple-darwin --output dist/release
```

Use the actual host target instead on another machine. The archive command
requires every expected binary and refuses to overwrite an existing archive.
It packages built files; it does not claim to cross-compile them.

After the owner approves pushing the reviewed source branch, these commands
request and download the six-target preparation run. Replace the branch only
if the reviewed branch has a different name:

```bash
test -z "$(git status --porcelain)"
RELEASE_COMMIT=$(git rev-parse HEAD)
git push origin HEAD:refs/heads/feat/rsb-v5.0.1
gh workflow run prepare-release.yml --repo samvallad33/vestige --ref feat/rsb-v5.0.1 -f source_ref="$RELEASE_COMMIT" -f version=5.0.1
gh run list --repo samvallad33/vestige --workflow prepare-release.yml --branch feat/rsb-v5.0.1 --limit 5
```

Select the run for the reviewed commit; do not infer the newest run is yours.
Set `PREPARE_RUN_ID` to that run's numeric ID, then:

```bash
gh run watch "$PREPARE_RUN_ID" --repo samvallad33/vestige --exit-status
gh run download "$PREPARE_RUN_ID" --repo samvallad33/vestige --pattern 'vestige-5.0.1-*' --dir dist/release-download
mkdir -p dist/release-assets
find dist/release-download -type f -name 'vestige-mcp-*' -exec cp -n {} dist/release-assets/ \;
python3 -B scripts/prepare-release.py verify --assets dist/release-assets
```

Keep this directory fresh for each reviewed build. SHA-256 checks establish
byte identity, not authorship or a trusted timestamp. Retain the successful
Actions run URL and commit alongside the downloaded assets.

## Stage and review npm packages

The init package pins all five desktop platform packages at **5.0.1**. The
memory-first installer requires an existing v5.0.1+ `vestige-mcp` on PATH (or an
explicit `VESTIGE_MCP_PATH`). It prints GitHub installation guidance and changes
no configuration when the binary is missing or older. It does not silently
replace an installed binary.
Android has a GitHub asset but no npm platform package.

The source workspace lock resolves unpublished platform versions to the local
workspace packages so frozen-lockfile CI can run before publication. Published
tarballs retain exact numeric `5.0.1` dependencies. The staging command copies
sources into a separate directory, verifies all six archive checksums and
members, places the four desktop binaries in each platform package, and pins
the staged meta and init packages. It never modifies the source manifest.

```bash
python3 -B scripts/prepare-release.py npm --version 5.0.1 --assets dist/release-assets --output dist/npm-5.0.1
mkdir -p dist/npm-tarballs
for package in mcp-darwin-arm64 mcp-darwin-x64 mcp-linux-arm64 mcp-linux-x64 mcp-win32-x64 vestige-mcp-npm vestige-init; do
  npm pack "./dist/npm-5.0.1/$package" --ignore-scripts --pack-destination dist/npm-tarballs
  npm publish "./dist/npm-5.0.1/$package" --dry-run --ignore-scripts --access public
done
```

Inspect the tarball file lists, versions and pinned dependencies. Verify npm
authentication and that none of these exact versions already exists before
publication; npm versions cannot be replaced. Authentication is an owner
terminal operation. A successful dry run is not a publication.

## Authorized tag, release and publication

The following effectful commands require current owner authorization.
Squash-merge the green PR through the repository's normal process first. Set
`RELEASE_COMMIT` to the resulting main commit and verify it has the exact tree
reviewed by the successful six-target build. Keep the working tree clean.

```bash
test -z "$(git status --porcelain)"
test "$(git rev-parse HEAD)" = "$RELEASE_COMMIT"
python3 -B scripts/prepare-release.py verify --assets dist/release-assets
git tag -a v5.0.1 "$RELEASE_COMMIT" -m 'Vestige v5.0.1: Retroactive Salience Backfill returns'
git push origin refs/tags/v5.0.1
gh release create v5.0.1 dist/release-assets/vestige-mcp-* --repo samvallad33/vestige --draft --verify-tag --title 'Vestige v5.0.1 — Retroactive Salience Backfill returns' --notes-file docs/releases/v5.0.1-notes.md
```

Review the draft and all assets before making it public. The existing product
release workflow also listens for GitHub's release-created event; inspect any
resulting workflow run and its source identity before accepting its assets.

Publish the five platform packages first, then the meta package and init:

```bash
npm whoami
for package in mcp-darwin-arm64 mcp-darwin-x64 mcp-linux-arm64 mcp-linux-x64 mcp-win32-x64; do
  npm publish "./dist/npm-5.0.1/$package" --ignore-scripts --access public
done
npm publish ./dist/npm-5.0.1/vestige-mcp-npm --ignore-scripts --access public
npm publish ./dist/npm-5.0.1/vestige-init --ignore-scripts --access public
gh release edit v5.0.1 --repo samvallad33/vestige --draft=false --latest
```

Finally, verify the public install from a disposable owner-controlled machine:

```bash
npx --yes @vestige/init@5.0.1 --dry-run --json
npx @vestige/init@5.0.1
vestige-mcp --version
vestige backfill --help
```

The first command only previews. The second changes that machine's install and
client configuration. Confirm the connected client advertises `backfill`, run
the Maya fixture against a fresh local store, and keep its change receipt.
Only then claim that the published installer connects the new binary.

Before shipping, source rollback means discard the isolated candidate or
revert its reviewed commits. For a store that has received v5.0.1 Backfill
writes, replacing only the binary is not a supported downgrade. Stop writers,
preserve the current store separately, and restore the verified pre-upgrade
backup together with its matching previous binary. This loses access to later
writes in the restored copy; preserve those original bytes for recovery.

After publication, do not move the tag or attempt to replace an npm version:
withdraw or deprecate the affected package as appropriate and ship a new patch
version after owner review.
