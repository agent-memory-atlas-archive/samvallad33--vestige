# Vestige v6.0.0 release record

What was checked on the release branch before its pull request, and what to do
before installing it over an existing store.

## Checked locally on release/v6.0.0

- `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`
  and `cargo test -p vestige-mcp` on the final tree, with every Reflex follow-up
  merged in and the version bumped.
- `cargo check --locked --workspace` after the version bump.
- `python3 scripts/prepare-release.py check-version --version 6.0.0` and
  `tests/test_prepare_release.py`.
- `npm test` in `packages/vestige-init`.
- Every Operator Lite suite under `operator-lite/`, old and new, on the newest
  Python and on the oldest one CI runs; `operator-gate.py corpus guardfall`;
  `operator-lite/npm/test.js`; the pip package's `test_smoke.py`; and every host
  port's `test.sh`.

The pull request's CI runs the full matrix, including the six target builds,
before the merge and the tag.

## Not rebuilt here

The embedded dashboard build in `apps/dashboard/build` is unchanged from 5.0.1.
Its SvelteKit app version string still reads 5.0.1; the dashboard does not poll
it, and the server reports its own version.

## Before installing over an existing store

Create and verify a complete Strata backup with the installed version first,
`vestige backup <new-empty-dir>`, and keep the previous binary. Reflex writes its
own state under `<data dir>/reflex/`; an older binary ignores that folder.

## Publishing

`release.yml` builds and attaches the six target archives when the release is
created. npm and PyPI publishing waits for the owner's review of a dry run.
